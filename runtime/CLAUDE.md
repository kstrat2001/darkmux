# The internal runtime (`runtime/`)

Claude Code loads this file when it works in this directory.

- This crate is NOT a workspace member: `cargo t-all` and workspace clippy never see it. Test it with `cargo t-runtime`; lint it with `cargo clippy --manifest-path runtime/Cargo.toml --all-targets -- -D warnings`. CI runs both.
- It ships two ways from one source (#3112). The `darkmux-runtime` binary (`src/main.rs`, built from this manifest and its own `Cargo.lock`) is the Docker image's entrypoint. The library (`src/lib.rs`, entry `main_with`) is also compiled into the darkmux binary by `crates/darkmux-runtime-linked`, a workspace member with no sources of its own, and run as the hidden `darkmux runtime …` subcommand: that is what a Seatbelt sandbox runs. A new dependency goes in both manifests (a test compares them).
- Inside darkmux, `serde_json` has `preserve_order` (feature unification), so a `serde_json::Value` keeps insertion order where the standalone build keeps every object sorted. A `Value` that leaves the process (a request body, model-facing text, a record) goes through `key_order::sorted`, which compiles to nothing in the standalone build. `cargo t-runtime-linked` runs this suite under that feature, and `cargo nextest run -p darkmux --test runtime_parity` runs both programs on the same fixtures and compares their bytes; CI runs both.
- It builds into the `darkmux-runtime` Docker image. A dispatch runs the image whose version label matches the binary, so a runtime change needs `docker build -t darkmux-runtime:latest runtime/` before a live dispatch can exercise it. A Seatbelt dispatch runs the copy inside the darkmux executable the dispatching process started from, and only while that file is still there: after a rebuild, `cargo install` or `brew upgrade`, restart the process (a running `darkmux serve` included), or the dispatch is refused.
- Text the runtime sends to a model (feedback-injection templates in `src/feedback.rs`, telemetry messages such as `STALL_NUDGE_MESSAGE`) follows the model-facing prompt rules in `templates/builtin/CLAUDE.md`.
