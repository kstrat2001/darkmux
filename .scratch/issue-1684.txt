**Hardening checklist from the frontier gate review of PR #1691** (verdict MERGE, zero must-fix; these CONSIDER findings are productization work and land under this issue):

1. **Orphan + temp leak on early error paths**: every `?` in the stderr loop can abandon the review child running (tokio `Child` is `kill_on_drop(false)` by default) and skip the temp-diff cleanup. Failure: Zed disconnects mid-review → multi-minute mission keeps burning models orphaned. Fix rides with cancellation: `kill_on_drop(true)` + a drop guard for the temp file.
2. **Stage recognition can move the plan BACKWARD**: `recognize_stage` substring-matches ANY stderr line — "prob" matches "problem", so a later-stage line mentioning "probe findings" re-activates a completed stage and re-emits its tool call. Cheap interim: only recognize stages on `[darkmux-liveness]`-prefixed lines. Real fix: #1687 (flow-stream truth).
3. **`choose_bundler` diff-shape gaps**: delete-only `.edge` diffs render `+++ /dev/null` → routed to the built-in bundler → guaranteed degenerate close (the exact failure the routing exists to prevent); 100%-similarity renames emit no `+++` line; `core.quotePath` non-ASCII paths render `+++ "b/..."` and miss the prefix strip.
4. **`panelize_comment` replaces `<sub>` globally** — a finding whose evidence quotes a literal `<sub>` gets corrupted. Tighten to the footer line only, or resolve properly via #1689 (target-aware render).
5. **`initialize` echoes any client protocol version** — should cap at the newest version the agent actually speaks (v1) per spec.
6. **Temp diff perms**: worktree diffs (private code) land in `temp_dir()` with default perms — world-readable /tmp on multi-user Linux (macOS `$TMPDIR` is per-user 700). Use 0600 or a private subdir.
7. **Pin the render contract with a test**: the chunk filter (`starts_with('{')`) and the buffered final-message parse both silently depend on `emit_rendered` staying compact single-line JSON; a future `to_string_pretty` would spray envelope interior into the chat while everything still "works."

(The eighth finding — CONTRIBUTING.md's stale MSRV — was fixed directly on #1691, the PR that caused the drift: 85d9e11e.)

Session-hygiene addendum from live dogfood: the acp process should **self-exit after N idle minutes** (no sessions, no in-flight runs). Today a binary swap requires an external `pkill`, which Zed surfaces to the operator as a scary "Failed to Launch — Server exited with status signal: 15 (SIGTERM)" banner on whatever thread was bound to the old process (observed live, twice). With idle self-exit, most swaps find no process running and "new thread = new binary" becomes true without any kill — the refresh UX papercut disappears structurally. Composes with the existing cancellation/lifetime items in this issue's checklist.

**Root cause of the recurring "Failed to Launch" after binary swaps — finally informative:** Zed's banner for a thread-RESUME attempt against our `loadSession: false` reads "Failed to Launch: Loading or resuming sessions is not supported by this agent." Not a spawn failure — every reopen of a pre-restart thread hits it, and it presents identically to the real spawn failures, which cost us two escalation ladders of misdiagnosis. Fix that retires the class: **minimal `session/load` support** — accept the resume, restore cwd, replay nothing. Commands are stateless views, so an empty-history resume is fully functional (Zed keeps the visible transcript; the shelf's restart loss is already doctrine). Pairs with the idle self-exit note above: together they make binary swaps invisible to the panel.
