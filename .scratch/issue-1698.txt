**Parsing contract (operator question surfaced it): the slash becomes the mode bit.** Today's parser first-token-matches with the slash OPTIONAL (`pr-view 42` invokes bare — spike-era convenience, test-pinned) and ignores command names mid-sentence. Harmless while unmatched text hits a help wall; ambiguous the instant free text gains meaning — "review this with me when you have a sec" must never race between launching the crew and routing intent. So when ANY interpreted layer of this issue ships: `/x` = law (exact command, zero interpretation); no slash = interpreted channel (router / grounded answers / authoring door); **bare-word invocation is retired in the same change**. Mid-sentence `/x` stays inert in both channels (the editor only intercepts leading slashes; the parser only reads the first token).

**Safety design (operator asked "what makes it safe?"): six walls, mostly inherited, not invented.**

1. **Mode bit boxes input** — the operator's keystroke (slash / no-slash) selects law vs interpretation before any model sees text; bare-word invocation retires the day interpretation ships.
2. **Selection-never-composition boxes output** — the router's answer space is the advertised registry (closed set): one command + args, or a refusal token. Structured output validated against the catalog; out-of-menu answers are unrepresentable, not caught. No chaining, no invention, no shell.
3. **Gates box consequence** — every state-changing route terminates at the sign-off dialog with facts; misroutes to reads waste seconds, misroutes to writes end at a dialog the operator rejects. Consequence always costs a human click. (This is why the gate mechanism shipping BEFORE the interpreted channel was the right build order.)
4. **Provenance boxes invisibility** — routed invocations say so in the render ("routed from your text") and drop a flow record with source text + chosen route. The misroute log IS the description-quality tuning loop.
5. **The answer seat has no hands** — grounded answers read the catalog + the session artifact shelf and emit prose: no tools, no dispatches, single exchange. Wrong is possible; *doing* is not.
6. **Fail closed** — low confidence → the help wall, never a guess; same pattern as unrecognized gate values. Uncertainty never degrades to permissiveness.

The architecture note: the safety walls (gates, provenance, closed registry, fail-closed) all predate the intelligence — interpretation arrives last, into a box already built.

**Packet B mode-bit investigation + live dogfood (#1702):**

Read the vendored `agent-client-protocol` v2.0.0 schema and empirically piped `darkmux acp` directly over stdin/stdout (a hand-rolled JSON-RPC driver, then the pipe-level test suite built for this packet). Finding: **the wire carries no structural marker distinguishing a menu-invoked slash command from freely typed text.** `PromptRequest.prompt: Vec<ContentBlock>`, and `ContentBlock::Text`'s `TextContent` has only `annotations`/`meta` — nothing command-shaped, in v1 or v2 of the schema. Whatever Zed's `/` menu does client-side, it must compose the command back into plain text (with the leading slash, per the existing slash-optional parser's own design intent) before sending it as an ordinary `session/prompt`.

The empirical probe also reproduced the exact ambiguity this issue named, live, under the PRE-fix parser: `"review this with me when you have a sec"` first-token-matched `review` and launched the full review pipeline (confirmed via `git diff HEAD` firing against a non-git `/tmp` cwd and failing loudly rather than silently — the mechanism fired, just against the wrong target). That's not hypothetical — the packet's own investigation triggered it.

Conclusion: the leading slash **in the text itself** is the only viable discriminator. Implemented per the mode-bit design — `/x` is law (leading-slash-required, bare-word invocation retired), no slash routes through the new interpreted channel.
